## Project Overview

SmartChatApp is an iOS AI chat application that connects to
OpenClaw Gateway, supporting streaming message output and
interactive content cards (music, video, buttons, images).

**Tech stack:** SwiftUI, iOS 17 Observation (`@Observable`),
XcodeGen, Swift Package Manager.

## Build & Test

```bash
# Generate the Xcode project (run after editing project.yml or
# Package.swift; the .xcodeproj is generated and not committed).
xcodegen generate

# Build for a connected device.
make install           # build + install
make build             # build only

# Build & test in the simulator (this is what CI uses).
xcodebuild test -scheme SmartChatAppTests \
  -destination 'platform=iOS Simulator,name=iPhone 17 Pro'
```

> **Info.plist is generated by XcodeGen.** `project.yml`
> `info.properties` is the source of truth — `xcodegen generate`
> rewrites `Info.plist` from those properties. To add a key, edit
> `project.yml` then run `xcodegen generate`. Editing `Info.plist`
> directly loses changes on the next regen.

## State Management

State lives in `@MainActor @Observable` classes. Each feature is a
single class file plus a SwiftUI view:

- `FeatureNameViewModel.swift` — `@MainActor @Observable final class`
- `FeatureNameView.swift` — `@State private var viewModel = ...`

`@MainActor` makes state mutations main-thread-safe; `@Observable`
drives SwiftUI re-renders. Long-running work is dispatched via
`Task { ... }` and hops back to main actor at the call site.

## Privacy Usage Descriptions

`Info.plist` (generated from `project.yml`) must declare every
`NS*UsageDescription` for any privacy-protected capability the app
actually invokes. **Without a matching key, the system silently
no-ops the permission request** — no prompt appears, the delegate
callback fires with `.denied` immediately.

| Capability | Required key | Status |
|------------|--------------|--------|
| Location (when in use) | `NSLocationWhenInUseUsageDescription` | ✅ added |
| Location (always) | `NSLocationAlwaysAndWhenInUseUsageDescription` | ✅ added |
| Camera / Photos / Mic / Contacts / Calendar / Reminders | (matching `NS*UsageDescription`) | ❌ not needed yet — `Core/NodeHandlers/` handlers for these are stubs |

When promoting a stub handler to a real implementation, add the
matching key to `project.yml` `info.properties` and re-run
`xcodegen generate` before testing the new handler. See the Node
Command Handlers table in `docs/ARCHITECTURE.md` for the full list
of stubbed commands.

## Logging

The app uses `AppLogger` (`Core/Services/AppLogger.swift`) as the
single entry point for log emission:

```swift
AppLogger.log("message", category: .network)   // default level .debug
AppLogger.log("oops", category: .nativeChat, level: .error)
```

`AppLogger` always writes to `OSLog` with the `SMAlog:` prefix
preserved for grep workflows. It additionally writes to an in-memory
ring buffer (cap 2000) when the matching category toggle in
Settings → Debug & Logs is on.

**Direct use of `os_log` / `Logger(subsystem:)` is not permitted in
app code** — use `AppLogger.log(...)` instead. The SDK-side
`Gateway Debug Logs` and `Discovery Debug Logs` toggles (in
Settings → Gateway → Advanced) are separate and control
`OpenClawKit` internal logging.

## Things to avoid

- **Don't edit `Info.plist` directly** — it's regenerated by
  `xcodegen`.
- **Don't commit `*.xcodeproj/project.pbxproj` changes** unless the
  commit is specifically about the project file (the regen noise
  pollutes diffs).
- **Don't use `gh api compare` + `git apply` as a sync shortcut** —
  it skips commit objects and leaves the branch pointer behind the
  working tree, causing non-fast-forward conflicts later.
- **Don't add a new `NS*UsageDescription` without verifying a real
  handler exists** — the privacy key table above is the source of
  truth for what the app actually invokes.
- **Don't add new top-level source directories without updating the
  `paths:` filter in `.github/workflows/ci.yml`** — pure-doc PRs are
  intended to skip the macos-15 build, but a new code dir not in
  the filter will silently skip CI on PRs that only touch that dir.

## Gateway Profile

All gateway connections go through `ProfileManager` +
`GatewayProfile` (`Core/Models/`). The Codable profile carries:
id, name, colorTag, host, port, token, tlsEnabled, isActive. Entry
points:

| Connection entry | Method |
|------------------|--------|
| App launch auto-connect | `SessionManager.ensureConnected()` (uses `activeProfile`) |
| Profile list Connect / Reconnect | `ProfileManager.switchToProfile()` → `SessionManager.connectWithProfile()` |
| Edit-profile manual URL | `SessionManager.connectWithRole()` |
| ChatList / NativeChat | `SessionManager.ensureConnected()` |
